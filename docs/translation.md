# 번역 동작과 품질 검증

## 문장과 문맥을 보존하는 번역

음성인식은 `large-v3`, 기본 번역은 `gemma4:e4b`를 사용하며 모든 처리는 로컬에서 진행합니다. 설정에서 옵션을 켜면 긴 문장과 복잡한 조건문에 설치된 `gemma4:12b`를 선택적으로 사용합니다. 일반 실행에서는 옵션이 꺼져 있습니다.

- 실제 오디오에서 **0.6초 침묵**이 감지되면 Whisper로 인식해 번역합니다. 별도의 LLM 문장 판별 요청은 보내지 않습니다. 큐가 비거나 입력이 끊긴 시간은 침묵으로 계산하지 않습니다.
- 접속사·전치사로 끝나는 구절 등 명백한 미완성 문장만 같은 오디오와 발화 ID를 유지해 다음 구절을 잠시 기다립니다. 추가 음성이 없으면 같은 문장을 다시 인식하지 않고 **1.2초 침묵**에서 확정합니다.
- 긴 발화는 **8초부터 4초 간격**으로 문장을 확인합니다. 시간만으로 문장 중간을 확정하지 않고, 완료된 문장만 먼저 번역하며 마지막 구절은 원래 음성과 함께 이어 받습니다. 단어 타임스탬프와 원문이 일치할 때만 음성을 잘라 중복·누락을 방지합니다. 인식기가 조건절 끝에 마침표를 붙여도 이어지는 주절과 합쳐 번역합니다.
- 인식 오디오가 **28초**에 이르면 단어 경계에서 인식 창을 옮깁니다. 미완성 원문은 보관해 다음 음성과 합친 뒤 번역합니다. 정렬을 신뢰할 수 없으면 음성을 버리지 않고 재확인합니다. 긴 문장에서는 완성된 한국어가 나올 때까지 더 기다릴 수 있습니다. 종료 시 마지막 음성도 처리합니다.
- 여러 문장이 한 번에 인식되면 문장별 번역 작업으로 나눕니다. 소수점·날짜·일반적인 영어 약어는 보수적으로 처리합니다. 문장 경계는 간단한 규칙을 사용하므로 긴 문장 중간에서 나뉘거나 일부 문장이 묶일 수 있습니다.
- 직전 6개 발화의 원문과 가능한 번역을 합계 4,000자까지 참고합니다. 번역에 실패한 원문과 한국어 발화도 문맥에 남습니다. 확정된 문장은 순서대로 처리하며, 번역이 밀려도 앞 문장을 건너뛰지 않습니다.
- 한국어는 생성이 끝난 뒤 한 번에 표시합니다. 512토큰 제한으로 잘리면 1,024토큰으로 한 번 재시도하고, 해당 모델에서 다시 잘리면 생성 실패로 처리하며 미완성 번역은 저장하지 않습니다. 긴 문장용 모델의 실패는 아래 기본 모델 대체 정책을 따릅니다. 스트리밍 모드는 영어 미리보기만 제공하고 한국어는 문장 확정 후 생성합니다.
- Ollama 예열과 실제 요청 모두 `num_ctx=8192`, `think=False`를 사용합니다. 추론 옵션이 지원되지 않는다는 명시적 오류가 있을 때만 해당 옵션 없이 재시도합니다. 지원 여부는 모델별로 기억합니다. 기본 모델은 다른 오류나 빈 결과에 대한 무조건적인 재요청을 하지 않습니다.

상태 표시에서 문장 수집, 다음 구절 대기, 번역 중인 작업의 대기 문장 수를 확인할 수 있습니다. 인식·번역 계산 시간과 작업 대기 시간은 위 침묵 시간에 추가됩니다.

회의록 옆의 `meeting_날짜_시간_performance.jsonl`에 음성인식, 번역 큐 대기, Ollama 입력 처리·생성 시간, 실제 사용 모델·선택 사유·기본 모델 대체 여부, UI 갱신 시간을 따로 기록합니다. 원문·번역 내용은 진단 로그에 넣지 않습니다. `seconds`로 끝나는 값은 초, Ollama의 `*_duration` 값은 나노초입니다. UI 시간은 화면 고정 중에는 측정하지 않으며 실제 화면의 물리적인 그리기 완료를 뜻하지 않습니다. 입력은 0.1초 단위로 캡처하며 큐는 기존과 같은 약 50초 분량을 유지합니다.

## 긴 문장용 모델 선택

설정의 **“긴 문장·복합 조건문에 12B 사용”**을 켜면 다음 원문은 `gemma4:12b`로 번역하고, 나머지는 기본 `gemma4:e4b`로 처리합니다. 선택을 위한 별도의 모델 호출은 없습니다.

- 원문이 40단어 이상인 경우.
- 조건 표현 `if`, `unless`, `provided that`과 시간 표현 `until`, `before`, `after`가 함께 있는 경우.

옵션은 이번 실행에만 적용되며 다음 일반 실행에서는 다시 꺼집니다. 화면 설정은 기존처럼 저장됩니다. 옵션을 바꾸면 대기 중인 문장도 다음 번역 작업을 시작할 때 새 설정을 적용합니다. 이미 시작한 번역과 재시도는 처음 선택한 모델로 완료합니다.

옵션이 꺼져 있으면 기본 모델만 예열합니다. 실행 중 옵션을 켜면 처음 해당 문장을 번역할 때 작업 스레드에서 12B를 준비하므로 시간이 추가될 수 있습니다. CLI로 처음부터 활성화하면 두 모델을 예열합니다. 두 모델은 이전 6개 발화·4,000자 문맥을 공유하며 `think=False`, `num_ctx=8192`, 512토큰 생성·길이 제한 시 1,024토큰 재시도를 사용합니다. 종료 요청 후에는 불필요한 추가 예열을 생략합니다.

긴 문장용 모델의 실행 실패·빈 결과·재시도 후 길이 초과가 발생하면 기본 모델로 한 번 대체하며, 화면에 대체 사실을 알립니다. 대체 모델에도 같은 길이 재시도 제한을 적용합니다. 모델이 없다는 오류는 세션 동안 기억해 반복 요청하지 않습니다. 두 모델 모두 실패하면 원문과 오류를 남깁니다. 모델을 자동 다운로드하지 않습니다.

```sh
# 기본: 모든 문장을 e4b로 번역, 설정에서 12B를 켤 수 있음
.venv/bin/python main.py
# 기본 모델만 사용
.venv/bin/python main.py --complex-model none
# 이번 실행에 선택적 12B 사용을 켬 (이후 UI에서 변경 가능)
.venv/bin/python main.py --model gemma4:e4b --complex-model gemma4:12b
```

UI에는 해당 문장을 처리하는 동안 “긴 문장 번역 중…”이 표시됩니다. 확정된 문장은 계속 FIFO 순서로 처리하므로, 짧은 문장도 앞선 긴 문장의 번역을 기다릴 수 있습니다. 현재 실행 중인 앱에는 코드 변경이 즉시 적용되지 않으며 다음 실행부터 적용됩니다.

고정 원문 24개(짧은 문장·긴 문장·조건문 각 8개)의 비교에서는 알려진 `postpone ... until` 의미 누락이 12B에서 해결되었습니다. 사전 점검 항목에 대한 에이전트의 수동 검토에서 주요 오류 사례는 1→0건이었지만, 각 방식에 기타 의미 문제 1건씩이 남았습니다. 독립적인 사람 평가나 일반적인 번역 정확도 보장은 아닙니다.

기존 앱을 실행한 상태에서 측정한 번역 생성 중앙값은 짧은 문장 1.05→0.88초, 긴 문장 2.39→5.57초, 조건문 1.18→2.68초였습니다. 긴 문장의 상위 95% 값은 10.92초였습니다. 두 모델은 비교 전후 메모리에 유지됐으며, 기록된 모델 로딩 시간은 최대 약 5.1ms였습니다. 이 수치는 음성인식·문장 대기·큐 대기·화면 표시 시간을 포함하지 않습니다. 선택적 모델은 속도보다 복잡한 문장의 의미 보존을 개선하기 위한 설정입니다.

재현 도구는 같은 원문과 같은 이전 대화 문맥으로 기본 모델만 사용하는 방식과 선택적 모델 사용을 비교합니다. 예문·의미 점검 항목은 `tests/fixtures/translation_quality.json`, 원문·결과·시간·수동 검토는 `output/quality/translation-comparison.json`에 있습니다. 실제 회의 내용은 사용하지 않습니다. `output/`의 보고서는 로컬 생성물이며 저장소에는 포함하지 않습니다.

```sh
.venv/bin/python -B scripts/benchmark_translation.py
# 알려진 실패 예문만 비교
.venv/bin/python -B scripts/benchmark_translation.py --case L01 --output output/quality/known-case.json
```

## 검증

오디오 장치, Whisper 모델, Ollama 서버 없이 테스트할 수 있습니다.

```sh
.venv/bin/python -B -m unittest discover -s tests -v
```

Qt 테스트는 오프스크린 모드로 실행합니다. 자막 고정 중 저장, 발화 ID 및 개정 번호 처리, 종료 시 큐 처리, 설정 저장, 다중 모니터 위치 보정, 화면 조작과 요약 저장을 검증합니다.

화면 검수용 이미지는 다음 명령으로 `output/ui/`에 생성합니다. 실제 회의 내용 대신 예시 문장을 사용합니다.

```sh
.venv/bin/python -B -m unittest discover -s tests -p preview_ui.py -v
```

실제 캐시된 모델을 사용하는 지연 비교 도구도 제공합니다. 설치된 macOS `Samantha` 음성으로 고정 샘플을 파일에 합성하며 스피커로 재생하거나 클라우드로 보내지 않습니다.

```sh
.venv/bin/python -B scripts/benchmark_latency.py --output output/latency/after.json
# 변경 전 소스 사본이 있을 때 동일한 샘플로 비교
.venv/bin/python -B scripts/benchmark_latency.py --source-dir /path/to/old/source --legacy --output output/latency/before.json
```

이 도구는 예열 후 발화 종료부터 침묵 대기·인식·문장 판별(이전 버전)·최종 번역까지의 시간을 샘플별로 측정합니다. 큐 적체나 UI 그리기는 포함하지 않습니다. 보고서에는 고정 예문의 인식·번역 결과와 중앙값·상위 95% 값이 포함됩니다. 샘플 수가 작고 합성 음성이므로 실제 회의 품질이나 지연을 보장하는 수치는 아닙니다.

## 앱 아이콘

`assets/zoomtrans.svg`가 원본이며, 파란색 말풍선과 `A`·`가`로 통역을 표현합니다. 앱 번들과 실행 중인 앱은 같은 아이콘을 사용합니다. 원본 수정 후 다음 명령으로 PNG·ICNS와 앱 번들 리소스를 갱신할 수 있습니다.

```sh
.venv/bin/python -B scripts/build_icon.py
```

긴 문장의 연결 동작은 다음 명령으로 실제 로컬 모델에서도 확인할 수 있습니다. 약 36초짜리 고정 조건문을 파일로 합성해 전체 파이프라인에 넣습니다. 보고서의 처리 시간은 오프라인 재생 처리 시간이므로 실시간 자막 지연과 다릅니다.

```sh
.venv/bin/python -B scripts/benchmark_latency.py --long-context --output output/latency/long-context.json
```

선택적 번역까지 포함한 긴 발화 전체 경로는 다음과 같이 확인합니다. 기존 기본 모델만의 `long-context.json`과 구분해 결과를 저장합니다.

```sh
.venv/bin/python -B scripts/benchmark_latency.py --long-context --complex-model gemma4:12b --output output/quality/long-pipeline.json
```
